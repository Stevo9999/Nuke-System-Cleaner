# Never-touch list (research, 2026-10-18)

Purpose: the places and registry areas this app (and the later registry cleaner) must refuse even if a scan, a user pick or a bug offers them.

## How reliable is this?
- Microsoft does not publish one complete list. What it does document ([About Windows Resource Protection](https://learn.microsoft.com/en-us/windows/win32/wfp/about-windows-file-protection), [Protected Resource List](https://learn.microsoft.com/en-us/windows/win32/wfp/protected-file-list)): Windows Resource Protection (WRP) guards essential system **files, folders and registry keys**; only TrustedInstaller may change them; apps that try to delete or change them "may fail" or break Windows. Protected file types include .dll .exe .sys .ocx .drv .inf .msc .msi .lnk and more. The exact folder and key lists are not on those pages (the API `SfcIsKeyProtected` answers per key).
- Web search found no authoritative third-party list. The entries below combine that Microsoft rule with standard Windows layout knowledge (my own, not one cited page). Treat them as a **deny-list floor**; the app's main safety is still "only fixed, known junk locations are ever offered".

## Folders (never offer, never delete, never walk into to delete)
- `C:\Windows` in full, in particular: `System32`, `SysWOW64`, `WinSxS` (and `WinSxS\Backup`), `Installer` (MSI cache: needed to repair/uninstall programs), `servicing`, `assembly`, `Boot`, `Fonts`, `INF`, `Microsoft.NET`, `Resources`, `PolicyDefinitions`, `System32\config` (the registry hives), `System32\DriverStore`, `System32\drivers`, `System32\catroot` and `catroot2`, `SoftwareDistribution` (only Windows Update may clean it).
- `C:\Program Files`, `C:\Program Files (x86)` (only a program's own uninstaller removes its folder), `C:\ProgramData\Microsoft` (Defender, Crypto, Windows settings).
- Drive-root system items: `\Boot`, `\Recovery`, `\System Volume Information` (restore points and shadow copies), `\$Recycle.Bin` of other accounts, `\$WinREAgent`, `\Windows.old` (Disk Cleanup only), `\pagefile.sys`, `\hiberfil.sys`, `\swapfile.sys`, `\bootmgr`, `\EFI`.
- Other accounts: `C:\Users\Default`, `C:\Users\Public`, `C:\Users\All Users`, every other user's profile.
- Inside your own profile: `NTUSER.DAT*`, `AppData\Local\Microsoft\Windows\UsrClass.dat*`, `AppData\Roaming\Microsoft\Protect` (DPAPI master keys: deleting them makes saved passwords/certificates unreadable), `AppData\Roaming\Microsoft\Crypto`, `AppData\Roaming\Microsoft\SystemCertificates`, `AppData\*\Microsoft\Credentials`, `.ssh`, `.gnupg`, and Desktop, Documents, Pictures, Music, Videos, Downloads, OneDrive (already protected in the app).
- Browser data that is not cache: Cookies, Login Data, Bookmarks, Extensions, Preferences, Local State, `places.sqlite`, `key4.db`, `logins.json` (round 2 tests assert these can never be produced).

## Registry (for the later registry cleaner; this version never writes the registry)
- Whole hives or areas: `HKLM\SAM`, `HKLM\SECURITY`, `HKLM\SYSTEM` (Services, Enum, Control, DriverDatabase), `HKLM\BCD00000000`, `HKLM\HARDWARE`, `HKLM\DRIVERS`, `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`, `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\{Policies, Component Based Servicing, Installer, Explorer, App Paths of Windows components}`, `HKLM\SOFTWARE\Policies`, `HKCU\SOFTWARE\Policies`.
- COM and Windows Installer registrations: `HKCR\CLSID`, `Interface`, `TypeLib`, `AppID`, `Installer`, `HKLM\SOFTWARE\Classes\...` and `HKCU\SOFTWARE\Classes\...` of the same names, `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Installer\UserData` (needed to repair or uninstall MSI programs).
- File associations and shell: `HKCR\.exe|.dll|.lnk|.bat|.cmd|.msc|.msi|.sys` and `HKCR\exefile|lnkfile|batfile|Folder|Directory|*`.
- `HKCU\Environment`, `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer` (User Shell Folders), `...\Run` entries the user did not ask to remove.
- Any key WRP protects (`SfcIsKeyProtected` true) or whose ACL denies delete to the user.
- Rule for the registry cleaner itself: only entries **provably orphaned** for one investigated program, a `.reg` backup first, and the restore-point prompt before deleting registry items (user requirement, PARKED.md).

## What the app does today vs this list
- Smart Scan offers only a fixed allow-list of junk locations (temp, caches, crash dumps, thumbnails, Recycle Bin of the current user, three admin folders: Windows Temp, WER archive/queue, Windows Update downloads); everything else is never offered, so System32, WinSxS, Installer, Program Files and the registry are unreachable by design.
- Picked files/folders (R45) must lie inside the user's own profile in standard mode; Documents/Desktop/Pictures/Music/Videos/Downloads/OneDrive and redirected known folders are protected roots.
- Gap found: sensitive profile areas that are NOT in the protected list: `AppData\Roaming\Microsoft\Protect`, `...\Crypto`, `...\SystemCertificates`, `Credentials`, `.ssh`, `.gnupg`, `NTUSER.DAT*`, `UsrClass.dat*`. A picked folder or a program leftover scan could in principle offer them. Recommended fix: a small hard deny-list module applied everywhere (scan time, selection time, delete time) with tests; plus a drive-root deny-list (`\Windows`, `\Program Files*`, `\ProgramData\Microsoft`, `\System Volume Information`, `\Recovery`, `\Boot`, `\Users\Default|Public`, other users' profiles) for items outside the profile. To be done after round 2 lands (it edits the same files).

## Registry deny-list ideas from an open-source cleaner (GitHub research, 2026-10-18)
Source read for IDEAS only: [RaneKun/Windows-Registry-Cleaner](https://github.com/RaneKun/Windows-Registry-Cleaner). Its terms are "free for personal use, no selling, keep it credited" - not an open-source license - so **none of its code, patterns or lists are copied into this project or this document**. We credit it on the in-app Credits page. Our own list must be written from Windows facts (the Microsoft pages above) and our own judgment. Other repos looked at ([Little Registry Cleaner](https://github.com/little-apps/LittleRegistryCleaner), [bob-pc-toolkit](https://github.com/gazlappy/bob-pc-toolkit), [Windows_persistence](https://github.com/ewilded/Windows_persistence/blob/master/REGISTRY.md)) gave nothing we use.

### Design lessons (our own wording)
- Use an **allow-list**: a registry cleaner should be able to delete only a few precisely described kinds of entry (an uninstall entry, an App Paths entry, a file-association or context-menu entry of one investigated program, single stale values in a few well-known lists), and refuse everything else. A deny-list is a second, independent layer.
- Categories that should be refused even if something looks orphaned: hive roots and top-level software/system keys; Windows Installer and COM class registrations (CLSID, Interface, TypeLib, AppID, Installer); core file-type and shell associations (.exe, .lnk, .bat, .cmd, .reg, .dll, folders, drives); machine policy; services and control sets; anything under the Windows protected-resource rules; the HARDWARE, SAM and SECURITY hives (also excluded from backups).
- Windows-owned program folders are never flagged as leftovers: the Windows folder, WindowsApps, Defender, Windows Media Player, Windows NT, Windows Mail, Windows Photo Viewer, Internet Explorer and PowerShell folders (the general facts are in the Microsoft documentation).

### Extra keys I recommend adding (security-sensitive persistence; my addition, supported by the persistence-key references above)
A cleaner cannot tell a legitimate entry from malware here, so these are report-only forever (the app only READS `Session Manager\PendingFileRenameOperations` once, after an uninstaller, to tell you a restart is pending; it never writes it): `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options`, `...\Winlogon` (Shell, Userinit, Notify), `...\Windows\AppInit_DLLs`, `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager` (BootExecute, PendingFileRenameOperations), `...\Control\SafeBoot`, `...\Control\Lsa`, `HKLM\SOFTWARE\Microsoft\Active Setup\Installed Components`, `...\Windows\CurrentVersion\ShellServiceObjectDelayLoad`, `...\Explorer\Browser Helper Objects`, `...\Policies\*`, `HKLM\SOFTWARE\Microsoft\Windows Defender` (incl. `Exclusions`), `HKLM\SYSTEM\CurrentControlSet\Services\*`, `HKLM\SYSTEM\CurrentControlSet\Enum`, `HKLM\SYSTEM\DriverDatabase`.

### Phase 2 consequence
Implement as `lib/registry-guard.mjs`: (1) exact allow-list patterns for deletable keys/values, (2) this deny-list as an independent second check (either layer refusing = refuse), (3) tests that every listed key is refused, with the guard applied at scan time, selection time and delete time, and a `.reg` backup before anything is deleted.
